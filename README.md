# Dawrah

An iOS app for revising Qur'an memorisation. It listens while you recite,
follows along, records the ayahs you got wrong, and schedules them back to you
on a spaced repetition rota.

Expo SDK 54, React Native 0.81, Supabase.

## Environment variables

Create `.env` in the project root. It is gitignored and must not be committed.

| Variable | Description |
| --- | --- |
| `EXPO_PUBLIC_SUPABASE_URL` | Supabase project URL. Required. |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon key. Required. Public by design; row level security is what protects the data, not this key. |

Both come from the Supabase dashboard under Project Settings → API. Copy
`.env.example` to `.env` to start.

There is no third variable. **The Speechmatics API key is deliberately not
here.** It is a server secret held by the `speechmatics-token` edge function,
which mints 60-second tokens for the app. Anything in `.env` is compiled into
the app bundle and readable by anyone who installs it, which is exactly why the
transcription key does not live there.

Server-side secrets, set in the Supabase dashboard under Edge Functions, not in
this repo:

| Secret | Used by |
| --- | --- |
| `SPEECHMATICS_API_KEY` | `speechmatics-token` |

Restart the dev server after changing `.env`. Expo reads it when the bundle is
built, so a running Metro will not pick up a change on its own.

## Which database a build talks to

Whatever `.env` says at the moment the bundle is built. Nothing in the build
process records it, so a release build inherits whatever the machine was
pointed at.

`lib/supabase.js` guards against the consequences: missing configuration fails
immediately with a clear message, a release build refuses to start against
anything other than the production project, and a dev build logs which database
it connected to on startup.

There is currently **one** Supabase project. Development and production share
it, which means a schema change is live for everyone the moment it runs. See
`POST-BETA.md` and `NEXT-SESSION.md`.

## Getting started

```bash
npm install
```

```bash
npm start
```

The app needs a development build rather than Expo Go, because it uses native
modules (audio capture, SQLite, notifications, Sentry). `ios/` is generated by
prebuild and must never be hand-edited: change `app.json` and re-run prebuild.

```bash
npx expo prebuild --platform ios --clean
```

## Database

`supabase/schema.sql` describes the whole database. `supabase/migrations/`
holds the ordered changes, `001` through `011`.

Migrations run against the live project. There is no staging database, so
anything destructive is destructive for real. While beta testers are active the
rule is: add, never rename or remove. Removing something safely means shipping
an app version that no longer uses it, waiting for testers to update, and only
then changing the database.

## Tests on a real phone

The simulator cannot exercise recitation, because that needs a microphone and
real speech. Anything involving transcription, mistake logging, or the quizzes
has to be checked on a device. Commit messages say explicitly when something
was verified by running it and when it was not.
